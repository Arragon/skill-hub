# unify-design · 公共单文件 Skill v1.0.1

> 此文件为方便公开在线阅读和 Agent 引用的独立版本。完整的原始 Skill ZIP 和 UI Kit ZIP 尚未作为 GitHub 附件发布。完整八场景可交互参考见 [index.html](./index.html)。

## 使用目标

设计、整改或审查信息密集的中文企业业务系统。优先追求清晰、紧凑、可靠、可追溯，不凭视觉效果牺牲业务能力。既有设计系统、技术栈、业务模型与权限控制是约束，不直接移植参考案例中的模拟业务。

## 设计语汇

- 页面浅灰，主内容白底；蓝色主交互，绿/黄/红表示真实语义状态。减少无效大标题、副标题、视觉容器和装饰性文案。
- 基础字体为系统中文字体，日志、路径、数值用等宽字体。使用统一 spacing、border、radius、typography tokens；高密度不等于压缩基本字体到不可读。
- 常用结构：全局顶栏 → 可折叠导航 → 主要工作区 → 选中对象详情。仅在复杂度有必要时启用全部区域。
- 工具栏按「定位 / 搜索筛选 / 主操作 / 次操作」组织。核心列表尽量高位开始，特别关注 1366×768 首屏可用纵向空间。

## 八类参考场景

1. 工作总览：待处理事项、异常、近期变更与直达动作，避免无信息的 KPI 卡片。
2. 参数矩阵：稳定对象 ID、层级树、可折叠、筛选、分页/按需加载；3,000+ 记录不能全部挂载 DOM。
3. 配置版本：真实前驱、分支、机台基线与来源关系；复杂关系提供表格/文字替代查看。
4. 日志探索：原文可追溯、错误高亮、规则筛选、详情与大文件处理进度。
5. 变更审批：待审/通过/驳回/发布状态明确分离，显示前后值和影响范围。
6. 文件资源：权威单入口，上传/导入/下载/历史集中管理，避免多个平行文件管理模块。
7. 组件图鉴：按钮、标签、表单、错误、弹窗、分页、通知、骨架屏等一致化。
8. 设计原则：语义色与排版/间距、响应式、焦点和可访问性验证。

## 开发 / 评审流程

1. 阅读当前产品代码、调用链、业务对象、用户已确认需求和既有约束。先确定成功条件、必须保留的能力与修改边界。
2. 先优化信息架构：清除重复创建按钮、重复上传入口、过高页头、无效说明。不要因为新原型没画到就删原有功能。
3. 使用共享的语义变量与组件；React/Vue/Angular 映射视觉语言即可，不要混用两套 DOM 所有权。
4. 数据区设计需考虑稳定 ID、选择/草稿同步、权限、锁定、空状态、错误恢复。严格区分未设置/null/空串/0/false、无测量和非法值。
5. 工作区切换覆盖全局业务数据、缓存、请求、未保存修改和异步回包；AbortSignal + epoch 防止旧数据串入新上下文。
6. 只有真实后端确认成功才能标记保存、审批或发布成功；演示交互必须标注为模拟。

## 必要验收

- 在 375×812、768×1024、1366×768 测试布局，检查主内容实际高度、末项能否触达、局部滚动、无整页无意横向溢出。
- 检查键盘操作、可见焦点、表单 label/错误关联、弹窗焦点与可恢复性。
- 检查大数据 DOM 数量、筛选与分页行为，避免只模拟 3200 条数据就宣称生产性能达标。
- 检查工作区 A→B→A、慢响应回包、未保存草稿、权限拒绝、只读及数据来源状态。
- 记录真实执行的测试指令、结果、未实现项和剩余风险。
