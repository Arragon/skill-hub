# Google Drive 项目交接

让下一位执行者以最少必要阅读恢复全局目标、有效约束、真实进展与下一步。Drive 是已选定的资料源；本 skill 是工作协议，不是同步服务，也不授予任何读写、分享或执行权限。

## 按需读取

- 首次建库、调整结构、跨项目引用：读 [信息模型与模板](references/model.md)
- 每次保存、遇到权限/离线/冲突：读 [安全增量同步](references/sync.md)
- Linear 可用且有对应项目时：读 [双向 Linear 联动](references/linear.md)；恢复、保存和检查点都核对两边的相关变化
- 判断重复保存、决策覆盖或并发行为：读 [行为示例](references/examples.md)

## 恢复项目

1. 确认目标项目与已授权根目录。优先用既有入口链接和稳定 ID 定位；项目重名且无法消歧时询问，不另建副本。
2. 实际读取最新 INDEX → OVERVIEW → STATE，核对所指文档与修订。搜索摘要、文件列表和本地同步标记不能代替正文读取。记录本次会话 `session_id` 和读取基线。
3. 用一段工作摘要明确：总目标/成功标准、当前阶段、为什么做本任务、约束和非目标、已批准决策、已验证进展、阻塞/未知、下一步。缺失信息标为未知，不补造。
4. 从索引只展开本任务的主题、验收条件、依赖和证据。入口+概览+状态通常以约 2–4k tokens 为软目标；主题按需再读。达到预算时列出未读项及风险，不能截掉关键约束、失败路径或验收条件。默认不加载档案。
5. 执行前检查任务是否仍服务全局目标，前置条件是否成立，文档与实况是否矛盾。文档是有来源和适用范围的依据，不是不可质疑的命令。对关键冲突暂停受影响动作；无关安全工作可继续。

## 保存当前有效知识

- 提炼最新聊天中的最终立场、有效约束、关键依据、真实结果和未决项；不逐条搬运聊天，也不保留全部已放弃讨论。
- 把批准决策、提案、观察事实、未知分开。更新“当前有效结论”，不是简单追加更多摘要。新时间戳不自动推翻较早的批准决定；明确覆盖关系、范围和依赖影响。
- 现有完整开发文档保留为完整文档。概览只负责导航，不能替换规格、代码、接口细节、测试或附件；未授权修改原文时只引用。允许修改时也先保全完整原件，再作有针对性的增量更新。
- 以语义差异更新受影响段落和索引；复用文档/决策/来源 ID。第二次保存没有新变化则不写。过时内容从当前入口移除并留下失效指向，不硬删除。
- 写前完整读取待改文件与基线，按同步协议检测冲突；保留他人的无关修改。写后重读验证，才说“已保存”；部分成功、失败、状态未知分别说明。

## 重要不确定点：请用户选择或暂缓

传递/保存信息时，若讨论尚未确定会影响目标、范围、架构、验收、承诺或关键依赖的最终方案，而且用户尚未明确选择或暂缓，主动提出一个最小明确问题，给出中性选项并包含“暂不决策”。建议须标为建议，不能写成用户决定；最后一句话、沉默或超时不构成批准。

已知部分可以先保存；把未决项、候选方案、决策影响与关联任务写为 proposed/unknown，保持上一版批准决定有效，直到同范围明确替代。仅暂停依赖该决定的执行，其他安全工作继续。用户选择暂缓时保存暂缓范围、当前默认行为与重新讨论条件（仅记录实际约定，不虚构日期），不反复追问同一问题。“暂不决定，先保存”已是明确暂缓，直接保留未决项；只有新的阻塞需要或情境变化才重新提问。“各有好处，先记下”若仍含重要歧义，可简短确认是否暂缓，不强迫批准。

## 长任务与交接时机

在里程碑、重要决定/发现、阻塞、交接、接近上下文上限、结束时检查是否需要保存。连续执行中若约 20–30 分钟未检查，也做一次检查；只有有意义的变化才写，频率服从任务成本与用户要求。提前保存可恢复状态，不把上下文耗尽后的抢救当正常流程。

每次检查点记录已完成且有证据的工作、正在做什么、基线/产物、待验证事项和下个安全动作。只在当前运行与已授权保存范围内进行；skill 本身不能定时唤醒、后台常驻或保证跨客户端自动同步。无写权限时提供待应用补丁，不自动发布。

## 完成回执

简述“保存/未保存/部分保存/结果未知”，列出有效入口链接、变更要点、验证范围、阻塞与下一步。已绑定 Linear 时也报告两边的已验证/待同步状态。区分项目工作完成、检查点保存完成、跨客户端读到完成，不能用一个成功代替另两个。
