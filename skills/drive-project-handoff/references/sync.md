# 安全增量同步

## 先判定真实能力

逐客户端、逐账户、逐目录核验；一个客户端成功不代表另一个也有权限。首次使用只做当前任务所需的最小读取；写入测试须已获授权，不能因 skill 自动进行。

| 实际能力 | 读取/更新方式 | 不能推断的能力 |
|---|---|---|
| Drive 原始 `.md` 文件 | 按 file ID 取真实字节；原位更新相同 file ID | 上传新文件不等于覆盖原文件；检索命中不等于正文可读 |
| 原生 Google Docs | 用原生正文读取/编辑；工具暴露修订保护时使用 | Markdown 导出不是无损副本，也不是双向编辑接口 |
| 本地同步的普通文件 | 读取正文并核对云端可见版本 | 本地保存不等于远端完成；另一客户端可能尚未读到 |
| `.gdoc` 等快捷方式 | 取其指向的原生文档 | 快捷方式本身不是完整正文，不能当 Markdown 覆盖 |
| 仅搜索/只读连接 | 获取可读来源，输出补丁/交接包 | 不宣称已经写回；不自行另建集成或改共享权限 |

优先用已授权的实时直接读取。若能力来自工具返回，以实际工具字段为准；不要假设每个封装都暴露 Drive/Docs API 的全部功能。原生文档的表格、图片、脚注、评论、格式、附件和权限不得被文本导出静默丢弃。

## 一次保存的协议

1. 确定范围：项目、目标文件、已授权操作，以及本次应保存的语义变化。没有新变化则结束，不更新时间制造假进展。
2. 读取基线：完整读取所有待修改文件（含分页/截断检查），记录 file ID、实际修订/摘要及读取时间；相关只读文档可按需读取。未读完整的文件不做全文替换。
3. 保全原件：现有完整开发文档在首次授权变更前保留可恢复的完整原始版本；原始文件可直接继续作为原件，不必为了做摘要复制。确需改原件时，在授权范围内保存完整副本/有意固定的版本，再验证可恢复性。普通历史版本不自动等于永久归档。原生富文档不能仅用 Markdown 导出冒充无损备份；无法保全则提交补丁，不覆盖。
4. 生成语义补丁：标识 `change_id/session_id/base_revision`；列出新增/替换/失效的稳定对象与受影响章节。保留未涉及内容、人工编辑、格式和附件引用。按语义查重，不仅按 change_id 查重；相同结论换说法不算新知识。
5. 检查变更：核对最新聊天在同一项目/范围内的最终立场与既有批准来源；传播必要的依赖失效标记。仅保存必要的决定依据，不保存原始聊天流水账。
6. 提交前再读当前修订，与基线比较。变化时重新读取完整新版本，做基线→本次修改→远端当前的三方合并；无关修改保留，同字段冲突不得猜测。按下面并发规则选写法。
7. 写入并验证：先写主题/状态/附件，逐一重读验证实际内容、关键完整性及引用；索引/发布指针最后更新，再重读。新建文件只能登记实际返回的 ID。一次多文件保存不是原子事务。
8. 回执：列出已验证、失败、未知和待应用项。保存记录可留最少的最近 change_id/修订与必要审计依据，不把 STATE 变成无限增长的日志。

## 并发与发布

- 有真实条件写/修订前置条件时使用；冲突失败后重新读取合并，不把失败改成无条件覆盖。条件写只保护它覆盖的对象，不提供跨文件原子性。
- 无条件写保护时，先有可验证的单写者协调：同一文档/发布入口同一时刻只由一个写入者负责，其他执行者提交补丁。文件里写 `locked: true`、时间戳或“我是写入者”不是锁，也挡不住人工同时编辑。
- 无法保证协调而存在并发可能时，不覆盖共享原件或指针；准备独立补丁，说明需要协调写入。最后一秒重读仍不能消除读写之间的竞态。
- 对需要一致交接的多文档成果，可在授权范围内生成不可变快照：新 `publication_id` 对应精确的完整文件/附件集合，写完逐一验证后才更新入口指针。这里“不可变”是协议约定，除非实际设置了权限，不宣称技术上只读。
- 快照成员引用固定 file ID/修订或内容摘要，不能混用可变的“最新”文件。指针写仍需条件写或单写者协调；快照机制不能伪装成分布式锁。读者先取指针、读取指定集合、再核对指针；变化则重新定位或继续明确固定的旧完整快照，不混读。
- 不把每次小保存升级成全库快照。普通单文档变更用增量编辑；仅发布一致性、迁移或有意归档需要快照。未完成发布保留为 pending，不从正式入口冒充 current。

## 失效、移动、失败与离线

- 废弃结论从当前正文撤出，留下简短 tombstone：稳定 ID、失效原因、替代 ID、作用范围和日期。历史详文按需归档；不硬删除源文件。重命名沿用 file ID，更新必要导航；移动不得改变原授权的共享范围。
- 写入超时：结果未知，先停后续依赖写并重读。目标内容与 change_id 均匹配才能确认；旧内容暂时可见不证明延迟写入绝不会发生。不要盲重试或重复创建。
- 部分发布：保留各文件实际成功/未知状态，停止推进正式指针；若指针也状态未知，读指针与所有引用核验。只有可验证安全的前向修复才继续；不以旧全文回滚覆盖他人的新内容。
- 离线/权限不足：在当前允许保存的位置留下 pending patch，含目标 ID、基线修订、语义差异、证据、风险和恢复指令；明确云端未确认。暂停依赖最新远端状态的危险动作；可继续不依赖该状态的安全工作。恢复连接后重新读取并合并，不能直接上传旧补丁或自动发布未批准决定。
- 用户若只要求生成交接文件，不隐含 Drive 上传、安装、改权限或持续监控授权。用户要求保存也不授权将敏感信息发送到未批准的新目的地。
