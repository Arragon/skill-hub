# Existing UI/UX Audit

## Evidence first
Audit the actual rendered experience or reliable screenshots/code evidence. Do not critique an imagined surface.

## Evaluate

1. user flow and task efficiency;
2. IA/navigation/findability;
3. information and visual hierarchy;
4. cognitive load and density;
5. layout rhythm, grouping, alignment;
6. typography hierarchy/readability;
7. color, contrast, semantic state communication;
8. component consistency;
9. interaction clarity and feedback;
10. loading/empty/error/disabled/success states;
11. responsive risks;
12. accessibility risks visible from available evidence;
13. generic/AI UI patterns that harm product fit;
14. polish-only issues.

## Rank findings
Use impact levels, not a flat complaint list:

- P0: blocks core task, causes serious error, or violates a critical contract;
- P1: materially harms comprehension, efficiency, accessibility, or consistency;
- P2: meaningful refinement;
- P3: polish/preferences.

For each P0/P1 finding include evidence, user impact, and the narrowest next stage needed (journey, IA, wireframe, visual direction, implementation, harden, etc.).

## Output
Start with the 3–7 highest-impact issues. Distinguish facts from judgment. State evidence limits.

## Prohibition
Do not modify production UI during audit.
