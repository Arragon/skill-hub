# Wireframe

## Input
Use approved or current journey, IA, content requirements, and relevant state inventory.

## Define

- page/viewport regions;
- information hierarchy;
- primary/secondary actions;
- controls and input placement;
- navigation/context cues;
- progressive disclosure;
- loading/empty/error/success placeholders where relevant;
- screen-to-screen continuity;
- responsive structural changes when they affect hierarchy.

## Fidelity
Keep styling deliberately simple. Use boxes, labels, text hierarchy, and basic CSS only if needed to make layout understandable.

## Output
Provide one recommended structure by default. Provide multiple alternatives only when a real unresolved structural tradeoff exists.

## Gate
Wireframe approval resolves structure; it does not authorize a different unreviewed visual direction later.
