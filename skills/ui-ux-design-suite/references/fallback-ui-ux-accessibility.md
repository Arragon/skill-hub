# Accessibility Design

Treat accessibility as interaction design, not only linting.

## Review/design

- semantic structure and control roles;
- accessible names/descriptions;
- keyboard-only path;
- logical focus order and visible focus;
- focus trapping/restoration for overlays;
- screen-reader order and meaningful announcements;
- contrast and non-color-only state communication;
- target size and motor demands;
- cognitive load and instruction clarity;
- error identification and recovery;
- reduced-motion behavior;
- zoom/reflow and responsive reading order;
- form labels, validation, required fields, and status feedback.

Use WCAG 2.2-relevant criteria as a baseline where applicable, but do not claim conformance without the testing needed to support that claim.

## Output
Concrete design/implementation requirements and remaining test limits.
