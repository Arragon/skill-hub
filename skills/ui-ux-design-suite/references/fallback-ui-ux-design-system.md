# Design System Direction

## Build only what the product needs
Define enough system to keep the approved surfaces coherent and future work predictable. Do not invent a giant component library for hypothetical needs.

## Define

- semantic color roles and theme behavior;
- typography roles and scale;
- spacing/sizing rhythm;
- borders, radius, shadows/elevation;
- focus and interaction states;
- density rules;
- layout/container conventions;
- core primitives and common composite patterns;
- navigation language;
- data-display conventions if relevant;
- motion principles;
- accessibility invariants.

## Reuse
If the project already has coherent tokens/components, extend them instead of replacing them. Extract new abstractions only after genuine repetition or durable need is established.

## Output
Write concise durable decisions suitable for DESIGN.md. Keep page-specific temporary values out of the global system.
