# UX Writing

## Scope
Use for interface language, not marketing copy unless the product surface requires it.

## Procedure

1. Preserve factual meaning, legal meaning, product terminology, and actual system behavior.
2. Define or enforce consistent terminology.
3. Make CTA hierarchy reflect action priority.
4. For errors, state what happened, what matters, and what the user can do next.
5. Use helper text only when it reduces uncertainty before an action.
6. Make empty states useful: explain the state and the next valuable action without over-teaching.
7. Keep success language concise, especially in high-frequency workflows.
8. Check labels under localization expansion and narrow layouts when relevant.

## System-level output
For broad work, define terminology, CTA patterns, validation/error patterns, confirmation patterns, empty-state voice, and tone under stress/success.

## Prohibitions
Do not invent product capabilities, guarantees, recovery actions, or backend behavior.
