# 架构设计与路线图交付契约

写正式交付物时使用本参考。结构服务于本次项目；用具体决策、契约和证据填充，不机械补齐无关章节。

## 架构设计部分

1. **目标与基线**：本次目标、非目标、范围；仓库/分支/提交与计划快照；已完成项、未完成项和证据差距。
2. **证据对照与决策**：需求或问题 → 源码/文档证据 → 原计划任务 → 保留、补齐或调整建议。重要结论附近附路径、行号或来源链接；明确事实、推断、假设和待验证能力。
3. **系统结构**：边界、组件职责、权威数据来源、执行所有权；标明复用、新增和改变的部分。需要时用 Mermaid 表达组件或关键时序。
4. **数据与接口契约**：关键字段、标识与作用域、输入输出、状态与错误语义。涉及持久化或外部调用时解释版本兼容、幂等、权限与失败恢复，避免只给类名和方框。
5. **关键操作链路**：用户从何处开始、看到什么状态、下一步如何操作；对应后台状态转换、失败/中断/恢复行为。工程细节放在技术说明，产品文案只显示对用户有用的信息。
6. **迁移、发布与验证**：从现状渐进到目标的步骤、兼容消费者、数据迁移/回滚（如适用）、本地检查与真实集成验收的分别要求。开放问题说明影响、证据需求与处理分支。

## 路线图部分

先给阶段/任务依赖总览与关键路径，再给任务卡。保留原计划 ID；新增规划 ID 不冒充已创建的外部 Issue。对重排、拆分和延期说明依据，保留完成项和原验收证据。

阶段退出 Gate 写成可观察条件，区分代码实现、本地回归、真机/真实供应商验收。项目计划中的完成百分比不能代替具体能力的验收。

### 任务卡的必要字段

| 字段 | 应写内容 |
| --- | --- |
| ID 与映射 | 稳定任务 ID；既有任务/里程碑；关联架构能力或决策引用 |
| 目标与边界 | 具体实现结果，以及本任务承担的责任 |
| 影响模块 | 已查证的文件/模块；拟新增路径显式标记为建议 |
| 输入与输出 | 依赖的契约/数据/探针结论；交付的接口、行为、产物或证据 |
| 前置依赖 | 明确任务 ID 与必须满足的条件；未知能力作为阻塞项 |
| 实现内容 | 足够指导执行的关键步骤，保持在本次路径和边界内 |
| 验收与验证 | 成功条件、重要负向/恢复条件、验证方式及证据产物；已确定命令或命令待确认的原因 |
| 风险与退出 | 阻塞项、失败后的处理；涉及迁移/外部副作用时的回滚或停止条件 |

### 示例：会话契约任务

- **ID/映射**：`N-02`，关联既有 `T-30`、架构 `CAP-SESSION`（示例编号）。
- **目标**：将内部 run 与真实 provider session 关联，保留现有执行所有权。
- **模块**：已查证的 Adapter 接口与 Runner 调用路径；新增 binding 存储路径由仓库布局确定，不伪装为已有文件。
- **输入**：`N-01` 探针的真实 session 身份、账户作用域及恢复结论。
- **输出**：明确的 start/resume 结果与错误语义、绑定数据契约、现有调用者适配。
- **依赖**：`N-01` 的身份探针通过；若 resume 未证明，保留禁用的恢复能力并阻塞接管发布。
- **验收**：恢复返回同一身份；身份不匹配被拒绝；结果未知不会静默创建第二个任务；旧调用者回归通过。真实供应商证明与测试替身结果分别记录。

该例只展示粒度；实际接口名称、持久化机制与停止策略必须从项目边界和探针结论推导。

## Harness/session 项目的额外核查

仅当本次方案涉及 coding harness 会话时使用：

- 分别查证后台执行、日志可见、官方历史、持久 session、同 session 续接、人工接管。PTY、Web 日志、配置模型或进程退出成功不能相互替代这些证据。
- 明确 Task/Run/native session 的身份映射、凭据作用域、worktree 所有权及人工/自动化交接协议。
- 保留真正隔离外部 provider 差异的 Adapter 边界。若需改变边界，说明调用者、迁移和影响，不能用 UI 直接调用 provider 来绕过。
- 接管设计包括写入互斥、旧执行端停止证据、失联/崩溃恢复与工作区连续性。未知状态不得被描述为安全交接完成。
- 讨论中的 harness 排名只是候选研究。选择依据必须来自本项目需求和当前能力证明，不固定选择某个供应商。

## 交付前审阅

依赖图中的每个 ID 都存在且无环；分阶段总览和任务卡条件一致。每项范围内架构能力都有任务和验收路径，所有任务都能追溯设计依据。标记清楚哪些检查已执行、哪些仅规划，以及哪些真实 Gate 仍待外部环境。
