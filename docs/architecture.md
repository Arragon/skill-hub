# 架构与边界

本仓库是手动加载的文档技能库，不是技能执行引擎、插件市场或同步服务。

## 调用链与所有权

各端固定引导 → 本仓库 ENTRY → 同版本 catalog 记录 → 本地技能包或登记的上游固定版本 → 当前 Agent 执行。
ENTRY 拥有加载协议；catalog 拥有 ID、来源、位置、依赖声明和状态；技能正文拥有具体方法；Agent 环境拥有工具、权限与实际执行。README 提供使用指令与维护流程，技能全表由 catalog 自动生成；它不成为独立维护的登记源。

`main` 解析出的 SHA 是一次调用的本仓库基线。每条外部记录的 `ref` 是独立上游基线。相对引用沿其来源仓库解析并固定到同一提交。下一次调用才使用更新，不做后台同步或持久缓存一致性系统。

## 登记契约

顶层 `schema_version=1`，`skills` 为记录数组，ID 全局唯一。

| 类型与状态 | 必需定位信息 | 行为 |
| --- | --- | --- |
| local / active | skills/<id>/SKILL.md | 完整读取正文与必要资源 |
| external / active | HTTPS GitHub 项目、40 位 SHA、相对入口路径、上游名称和入口散列 | 只引用，不复制正文 |
| external / reference-only | 项目地址及 reason | 不执行，仅展示来源缺口 |

所有记录携带 description、requires、provenance、license。`requires` 是快速筛选，不替代正文中的实际依赖。`entry_sha256` 记录外部入口原始字节 SHA-256，工具若可取得原始字节可验证；无法核验散列时不得声称完成散列核验，但仍可依靠 GitHub 固定提交读取。读取内容不完整或固定提交无法确认时停止加载。

`active` 只表明该入口可定位。工具权限、服务可用性、第三方脚本执行与跨客户端验收均是独立条件。外部条目的 license 是来源元数据，不是本库授予的许可。

## 失败与维护边界

未知 ID、无法完整读取、无法固定版本、必要依赖缺失、循环依赖分别报告；不静默换源或编造正文。已知可独立执行的步骤可以继续，但要说明部分完成。

结构校验使用 Python 标准库，不依赖本地 Codex 路径。它检查文档链接与包内引用、登记完整性及平台专属文件；不运行任意技能、不写外部系统，也不保证所有字符串形式的动态引用均可静态解析。

`scripts/readme_catalog.py` 从登记表的 ID、description、来源版本和状态生成 README 标记区域，包含全部条目和统计；其余段落保持原文。`scripts/validate.py` 检查生成区与登记表一致，防止遗漏、过时用途或状态、重复维护和统计漂移。新增、更新或删除技能时只维护登记表，再显式刷新技能表。

规则、登记字段或来源策略变化属于架构变化；单个技能正文修正通常只需要修改相关包及验证。
